# Evaluation methodology and interpretation

The original 40-case MVP dataset and its historical results remain preserved. `financial-v2.json` adds CPI factual research, cross-report comparisons and a revision-sensitive conflict case. It contains 52 questions, including 44 positive questions and 8 unsupported questions. Forty-eight positive source/page labels were checked against the original downloaded PDF hashes and text anchors. Verification normalizes whitespace, including the insignificant space before a percentage sign, without changing numerical values. This is automated reference verification; independent human relevance adjudication is still pending.

## Retrieval comparison

Run `python scripts/run_profile.py native -m evaluation.benchmark_v2`, then `python scripts/run_profile.py native -m evaluation.compare_retrieval`. Each configuration uses the same corpus, k=5, questions, report filters and page labels. Many factual questions name/filter a report, which makes retrieval easier than unconstrained general research. This is a development benchmark, not held-out evidence of generalization.

Page Recall@5 counts labeled source pages recovered in the five passages. MRR@5 uses the first passage on a labeled page. Page labels are not exhaustive chunk-level judgments and can hide within-page irrelevance. Keyword uses English full-text ranking, vector uses cosine, hybrid uses equal-weight reciprocal rank fusion with constant 60 and top-60 candidates per channel. Candidate comparison runs before answer gates to separate ranking from abstention.

The measured saved comparison recovered 1.0000 page recall with keyword and hybrid retrieval, versus 0.9773 with vector retrieval. MRR was 0.9773 keyword, 0.7803 vector and 0.9375 hybrid. Hybrid did not outperform keyword on this dataset. Latencies include model/cache warm-up and ordinary local execution rather than a controlled load test. See `evaluation/results/retrieval-comparison.json` for actual timings, corpus hashes and per-question ranks.

## Generated-answer evaluation

`python scripts/run_profile.py native -m evaluation.evaluate_rag` runs real model inference. `--balanced` selects 32 cases covering 24 factual questions, 4 unsupported questions and 4 cross-report/revision cases, to bound CPU evaluation time. The report records exactly which cases ran. It saves progress after every completed case; interrupted runs are marked running and must not be described as completed.

Quote/citation correctness checks every generated claim against the retrieved original text, source document and page. Extractive claim support is exact-source support, not a semantic relevance or human truth score. Because the application publishes only validated quotations, this score is partly guaranteed by design. A model can still select a true but irrelevant quote, miss a requested statistic or abstain on sufficient evidence. Expected-anchor coverage and positive-question abstention expose some of those failures; they are heuristic diagnostics, not answer accuracy.

Unsupported abstention measures the actual answer flag on questions deliberately outside the corpus. Cross-report cases require evidence from both selected reports; conflicting publication vintages must be displayed without silently reconciling values. The revision case contrasts the reported 2024 nominal GDP values in the 2024 and 2025 reports and warns against asserting a cause beyond cited evidence.

Provider token usage, latency and available estimated API fee are measured per question. Local inference has zero cloud API fee; CPU time, memory, hardware and energy are not priced. Cloud estimates require operator-supplied prices, and Gemini thinking tokens are included where returned. Invalid or blocked provider outputs abstain. Human-verified accuracy and independent semantic entailment remain unmeasured, not fabricated.

Model trials are not silently promoted to a successful result. The initial 0.5B local model paraphrased requested quotations and selected irrelevant facts or abstained excessively. Exact quote validation rejected unsupported paraphrases. A 1.5B calibration also selected a true CPI methodology sentence instead of the requested annual percentage. That failure is preserved in `local-rag-before-sentence-reranking.json`. Semantic sentence reranking and numeric-intent context selection were added in response, without relaxing exact-source validation. The first 32-case generation run had exact quote/citation integrity but only 0.6071 expected-anchor coverage: growth was confused with contribution, annual with quarterly growth, and nominal GDP with per-head values. That complete run is preserved in `rag-before-measure-guards.json`. Additional measure/quarter filters, complete numeric context and a strong lexical fallback for hybrid retrieval were added before a new full run. These are development fixes, not evidence of held-out improvement. The final provider/model run and its failures are recorded in `rag-latest.json`; current claims must follow that artifact rather than a successful code import or mocked provider test.

## Tests and artifacts

`python scripts/run_checks.py --postgres --models` runs deterministic tests plus isolated real PostgreSQL schema/migration/persistence and Sentence Transformers integration. Test schemas are created only in a dedicated `_test` database and are removed after each test. PostgreSQL restart and reader privileges were also verified against the actual corpus. Docker execution, cloud billing/live provider behavior, independent human review and production load testing remain separate verification tasks.

The current client_round_trip_ms diagnostic includes request construction and reference checking, not isolated transport latency. Server-reported latency is recorded separately. New runs include policy and backend-source hashes; checkpoints are published atomically for the Evaluation page.

## Final holdout and review package (17 November 2026)

The preserved development benchmark above was used for tuning. A new 30-question holdout was constructed only after freezing backend hashes, with 26 original PDF page/hash/anchor references verified and 6 unsupported/adversarial requests. New CPI periods, selected urban indices, fiscal GDP, industrial production, PPI methodology and cross-report comparisons broaden coverage. Half the first twelve CPI questions omit source filters. The author is the same development agent; templates remain related to development tasks, so this is not independent human-authored validation.

Backend source hashes remained unchanged throughout inference. All 30 actual FastAPI requests completed. Saved results: `evaluation/results/holdout-rag.json`; configuration comparison: `holdout-retrieval.json`. Keyword Recall@5/MRR@5: 1.0000/0.8646; vector: 0.6458/0.2431; hybrid: 0.7500/0.3611. Reference pages are exact PDF pages; equivalent evidence elsewhere can reduce page-recall without being an incorrect citation.

The hybrid answer run generated 18 responses. All emitted claims passed exact-source/page/citation checks. Six supported questions were unnecessarily refused, while all six unsupported questions were refused. Expected-anchor coverage was 10/24 (41.7%); mean server latency was 17.764 s across all thirty requests including fast refusals. Actual token counts were 8,496 prompt and 1,686 completion tokens, with zero cloud API fee for local inference. This does not price hardware or energy. No independent semantic judge or human accuracy score was fabricated.

Fourteen diagnostic failures are retained in `holdout-failure-cases.json`: six unfiltered CPI questions unnecessarily refused; several selected-index questions answered with general CPI or chart/table text; the methodology case selected a table fragment; both comparisons selected headings rather than the requested annual statistics. The snapshot corpus was not changed during the run. No retrieval/prompt/answer tuning followed inspection of these holdout outcomes. Improving those patterns requires separate development examples and a new untouched evaluation set; this holdout cannot be reused as an unbiased final score after tuning.

`evaluation/human-review/` contains 30 shuffled provider-anonymized question/answer/reference packets, blank CSV ratings, a separate blinding key and an explicit rubric for financial measure, period, citation, completeness and abstention checks. Human-reviewed count remains zero. Two independent financial researchers should score before adjudication. Exact quotation and anchor coverage must never be reported as human-verified answer faithfulness.
