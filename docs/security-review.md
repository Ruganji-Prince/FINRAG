# Security review, 17 November 2026

Scope: repository code/configuration, local installed environment, operator ingestion and actual loopback API. This is an engineering review, not a penetration-test certification or a financial-institution security approval. The full native/model test suite and security HTTP artifact record what was actually exercised.

| Area | Implemented control and evidence | Remaining limit |
|---|---|---|
| API access | Optional shared bearer token; public mode refuses startup with a token shorter than 32 characters. Constant-time comparison protects data, governance, evaluation, docs and OpenAPI. Real HTTP verifies anonymous 401 and authenticated 200. Health stays public. | Local mode intentionally permits anonymous loopback access. No SSO, user roles, tenant isolation or token rotation service. |
| Request abuse | Actual streamed body cap 32 KiB, validated query length/k/filter bounds, per-process 60/minute IP window, 5-second local generation lock acquisition, 320 output-token cap and 90-second generation stopping budget. | Generation stop is checked between decoding steps, not a hard process kill. Not distributed rate limiting. A gateway is required for public multi-user service. |
| Cloud calls | Fixed provider endpoints; credentials in environment; 60-second HTTP timeout, 10-second connect timeout, at most two attempts for explicit 429/503 or connection failure. Read timeouts are not retried to avoid duplicate billed generations. Failure leaves evidence visible and abstains. | Adapters have mocked contract coverage only; no valid cloud credentials were supplied. Successful usage/cost returned per response; failed/invalid billable responses are not a complete billing ledger. No automatic provider switching or paid fallback. |
| Prompt/answer injection | Evidence treated as untrusted data; local decoder chooses only original source quotations or refusal; cloud outputs require valid IDs and exact source/context quotations. Explicit secret-disclosure and fabrication requests refused before retrieval/generation. | Exact quotations can be irrelevant or contextually misleading. Heuristic defenses do not establish immunity to every injection. No autonomous tools or transactions are exposed. |
| Unsupported/outdated/conflicting data | Current/latest requests refused, measure/frequency/period gates, page citations, publication dates and comparison-vintage warning. Contradictory reported values are displayed as source evidence, never silently reconciled. | No general contradiction resolver or automatic accounting reconciliation. The holdout reports unnecessary abstention and measure-selection failures. Human review is pending. |
| Documents/SSRF | Operator-only ingestion; HTTPS official-host allowlist, no redirects, robots checks, two-second download spacing, 25 MB cap, PDF signature/page/metadata/text-quality checks, SHA256 dedup and audit. Raw/review files are excluded from release. | No public upload/ingestion endpoint. PDF parsing is not in an isolated resource-limited worker; decompression/parser denial-of-service remains an operator risk. Scanned material requires review; no OCR claim. |
| Database | Separate admin/writer/reader roles, SCRAM, loopback binding, disabled serving DDL, parameterized queries, transactional checksummed migrations. Native reader denial and PostgreSQL persistence/integration tested. | No managed TLS/backup scheduler/HA configuration has been verified. Operator native secrets remain local and must be rotated for another host. |
| Secrets/publication | Ignore rules plus publication allowlist; exact configured-secret and credential-pattern scanning; no raw PDFs, DB files, caches, logs, models, runtime or backups in the bundle. Generated scan lists filenames/rules without secret values. | Pattern scanning is not proof of absence of all sensitive information. Review release manifest before publishing. No existing history was rewritten. |
| Logs/errors | Logs contain path, status and duration; generic client errors. Unexpected exceptions log class only, avoiding provider exception strings containing credentials. Cache disabled and content-sniff/frame headers set on completed responses. | Uvicorn/host logs still need retention and access policy. Health discloses model/backend identity. No SIEM or alerting. |
| Dependencies | Initial installed-environment pip-audit found 25 advisory entries across four packages. Upgraded pip/setuptools/Transformers/Sentence Transformers and transitive pins. Upgraded audit reports zero known findings; real model calibration and native integration pass. | Audit is a point-in-time advisory check of this installed environment, not a container-image scan. Rerun regularly. No claim of zero unknown vulnerabilities. |
| Source rights | NISR data/analysis terms checked, per-document restriction text inspected, attribution and hashes retained. BNR candidates remain pending permission and absent from index/snapshots/release PDFs. | Rights review is documented engineering diligence, not legal certification. Embedded restrictions override general terms. |

Evidence: `evaluation/results/security-http-verification.json`, `dependency-audit.json`, `dependency-audit-upgraded.json`, `final-tests.xml`, `corpus-30-verification.json`, `database-verification.json`, `persistence-verification.json`, and the release secret scan. New security tests cover authentication, fail-closed public configuration, streamed body limits, bounded retries, ambiguous timeout behavior, generation backpressure and explicit prompt-injection refusal. Existing tests retain citation, scope/frequency, malformed/scanned PDF, unsafe URL, deduplication and governance-history coverage.

Production gaps: independent penetration testing, isolated PDF workers, enterprise identity/authorization, distributed quotas, monitoring/alerts, restore drills, cloud-provider live verification and realistic concurrent-load testing. The application remains a production-oriented research demonstration.
